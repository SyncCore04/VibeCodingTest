## 2. 数据库设计

```sql
CREATE TABLE t_user (
    id          BIGINT       AUTO_INCREMENT PRIMARY KEY COMMENT '主键ID',
    username    VARCHAR(50)  NOT NULL              COMMENT '用户名',
    phone       VARCHAR(20)  NOT NULL              COMMENT '手机号',
    email       VARCHAR(100) DEFAULT NULL          COMMENT '邮箱',
    create_time DATETIME     DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    deleted     TINYINT      DEFAULT 0             COMMENT '逻辑删除: 0未删除 / 1已删除',
    INDEX idx_username (username),
    INDEX idx_phone (phone)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

**关键设计点：**

| 字段 | 说明 |
|------|------|
| `id` | `AUTO_INCREMENT` — 数据库自增主键，MyBatis-Plus 的 `@TableId(type = IdType.AUTO)` 对应 |
| `deleted` | **逻辑删除标记**，0=正常，1=已删除。配合 `@TableLogic` 注解，MyBatis-Plus 会自动将所有查询、删除操作转换为逻辑操作 |
| `create_time` / `update_time` | 时间戳字段，由 `MetaObjectHandler` 自动填充，无需手动赋值 |
| 索引 | `username` 和 `phone` 建了索引，加速搜索查询 |

> **为什么用逻辑删除？** 物理删除 (`DELETE FROM`) 会真正删除数据，无法恢复。逻辑删除只是打一个标记，数据仍在，可以追溯、恢复、满足合规要求。MyBatis-Plus 配置后，调用 `removeById()` 实际执行的是 `UPDATE t_user SET deleted=1 WHERE id=?`。

### 3.2 application.yml — 核心配置

```yaml
server:
  port: 8080                          # 应用端口

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/user_manage?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
    username: root                    # 数据库用户名
    password: root                    # 数据库密码
    driver-class-name: com.mysql.cj.jdbc.Driver

mybatis-plus:
  global-config:
    db-config:
      logic-delete-field: deleted     # ← 逻辑删除字段名
      logic-delete-value: 1           # ← 已删除时的值
      logic-not-delete-value: 0       # ← 未删除时的值
  configuration:
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl  # SQL 日志输出到控制台
```

**三段关键配置解读：**

1. **`server.port`** — 应用监听端口，默认 8080
2. **`spring.datasource`** — 数据库连接信息，`serverTimezone=Asia/Shanghai` 指定时区，避免时区报错
3. **`mybatis-plus.global-config.db-config`** — MyBatis-Plus 全局配置：
   - `logic-delete-field: deleted` — 告诉框架用 `deleted` 字段做逻辑删除
   - `logic-delete-value: 1` — 标记删除时的值
   - 配置后，**所有 `SELECT` 自动追加 `WHERE deleted=0`**，**所有 `DELETE` 自动变为 `UPDATE SET deleted=1`**

### 3.3 Entity 层 — 实体与校验注解

```java
@Data                                   // Lombok：自动生成 getter/setter/toString/equals/hashCode
@TableName("t_user")                    // MyBatis-Plus：映射到数据库表 t_user
public class User {

    @TableId(type = IdType.AUTO)        // 主键自增
    private Long id;

    @NotBlank(message = "用户名不能为空")   // JSR-303：不为空字符串
    private String username;

    @NotBlank(message = "手机号不能为空")
    @Pattern(regexp = "^1[3-9]\\d{9}$", // JSR-303：正则校验手机号
             message = "手机号格式不正确")
    private String phone;

    private String email;               // 选填，不加校验注解

    @TableField(fill = FieldFill.INSERT)          // 插入时自动填充
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)   // 插入和更新时自动填充
    private LocalDateTime updateTime;

    @TableLogic                          // MyBatis-Plus：标记为逻辑删除字段
    private Integer deleted;
}
```

**注解作用链条：**

```
@NotBlank / @Pattern          @TableLogic           @TableField(fill=...)
       │                           │                       │
       ▼                           ▼                       ▼
  Controller 接收参数时       Mapper 执行 SQL 时       MetaObjectHandler
  @Valid 触发校验            自动追加 deleted=0         自动填入当前时间
```

> **新手提示：** `@Data` 是 Lombok 提供的最常用注解。编译时会自动生成所有字段的 getter/setter 方法，以及 `toString()`、`equals()`、`hashCode()`。你不需要手写这些方法。

> **正则解析：** `^1[3-9]\d{9}$` 的含义：
> - `^` — 字符串开头
> - `1` — 第一位必须是 1
> - `[3-9]` — 第二位是 3~9（覆盖所有中国手机号段：13x、15x、18x 等）
> - `\d{9}` — 后面 9 位任意数字
> - `$` — 字符串结尾
> - 总共恰好 11 位

### 3.4 Mapper 层 — 数据访问

```java
@Mapper
public interface UserMapper extends BaseMapper<User> {
    // 不需要写任何方法！
    // 继承 BaseMapper 即拥有以下内置方法：
    //   insert(User)           → 新增
    //   deleteById(Long)       → 删除（逻辑删除）
    //   updateById(User)       → 更新
    //   selectById(Long)       → 按ID查询
    //   selectList(Wrapper)    → 条件查询
    //   selectPage(Page, Wrapper) → 分页查询
}
```

> **MyBatis-Plus 的核心优势：** 你只需定义一个接口继承 `BaseMapper<实体类>`，就能获得全套 CRUD 方法，**零 XML、零 SQL 手写**。复杂查询通过 `LambdaQueryWrapper` 构建（见 Service 层）。

### 3.5 Service 层 — 业务逻辑

**接口定义：**

```java
public interface UserService extends IService<User> {
    // 自定义分页查询方法
    Page<User> pageQuery(Integer current, Integer size, String keyword);
}
```

继承 `IService<User>` 获得 `save()`、`updateById()`、`removeById()` 等方法。

**实现类：**

```java
@Service
public class UserServiceImpl
        extends ServiceImpl<UserMapper, User>   // 继承获得默认实现
        implements UserService {

    @Override
    public Page<User> pageQuery(Integer current, Integer size, String keyword) {
        // ① 创建分页对象
        Page<User> page = new Page<>(current, size);

        // ② 构建查询条件（Lambda 表达式，类型安全）
        LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();
        if (StringUtils.hasText(keyword)) {
            wrapper.and(w -> w
                .like(User::getUsername, keyword)   // WHERE username LIKE '%keyword%'
                .or()
                .like(User::getPhone, keyword)       // OR phone LIKE '%keyword%'
            );
        }

        // ③ 排序
        wrapper.orderByDesc(User::getCreateTime);    // ORDER BY create_time DESC

        // ④ 执行分页（自动追加 WHERE deleted=0）
        return this.page(page, wrapper);
    }
}
```

**`LambdaQueryWrapper` 的优势：**

传统 MyBatis 写法（字符串拼字段名，重构易出错）：
```java
wrapper.eq("username", keyword);  // 字段名是字符串，IDE 无法检查
```

Lambda 写法（编译期检查，重构自动更新）：
```java
wrapper.eq(User::getUsername, keyword);  // IDE 可跳转、可重构
```

**分页执行流程：**
```
前端请求: GET /api/users?page=2&size=10&keyword=张三
                  │
                  ▼
         pageQuery(2, 10, "张三")
                  │
                  ▼
    ┌─────────────────────────────────────┐
    │ MyBatis-Plus 拦截器自动拼接 SQL：    │
    │                                     │
    │ SELECT COUNT(*) FROM t_user         │  ← 先查总数
    │ WHERE deleted=0                     │  ← 自动追加
    │   AND (username LIKE '%张三%'        │
    │        OR phone LIKE '%张三%')       │
    │                                     │
    │ SELECT * FROM t_user                │  ← 再查当前页数据
    │ WHERE deleted=0                     │
    │   AND (...)                         │
    │ ORDER BY create_time DESC           │
    │ LIMIT 10 OFFSET 10                  │  ← 自动追加分页
    └─────────────────────────────────────┘
```

### 3.6 Controller 层 — REST 接口

```java
@RestController                    // = @Controller + @ResponseBody（返回 JSON）
@RequestMapping("/api/users")      // 所有接口路径前缀
@Validated                         // 开启类级别参数校验
public class UserController {

    private final UserService userService;

    // 构造器注入（推荐方式，无需 @Autowired）
    public UserController(UserService userService) {
        this.userService = userService;
    }

    // GET /api/users?page=1&size=10&keyword=xxx
    @GetMapping
    public Result<Page<User>> list(
            @RequestParam(defaultValue = "1") Integer page,    // 默认第1页
            @RequestParam(defaultValue = "10") Integer size,   // 默认每页10条
            @RequestParam(required = false) String keyword) {  // 可选参数
        return Result.ok(userService.pageQuery(page, size, keyword));
    }

    // POST /api/users   — 新增
    @PostMapping
    public Result<Void> add(@Valid @RequestBody User user) {
        // @Valid 触发 JSR-303 校验，不通过则抛出 BindException
        userService.save(user);
        return Result.ok();
    }

    // PUT /api/users/{id}   — 更新
    @PutMapping("/{id}")
    public Result<Void> update(@PathVariable Long id,
                               @Valid @RequestBody User user) {
        user.setId(id);
        userService.updateById(user);
        return Result.ok();
    }

    // DELETE /api/users/{id}   — 逻辑删除
    @DeleteMapping("/{id}")
    public Result<Void> delete(@PathVariable Long id) {
        userService.removeById(id);  // MyBatis-Plus 自动转为逻辑删除
        return Result.ok();
    }
}
```

**REST 设计对照表：**

| HTTP 方法 | 路径 | 用途 | 幂等性 |
|-----------|------|------|--------|
| `GET` | `/api/users` | 分页查询 | ✅ 幂等 |
| `GET` | `/api/users/{id}` | 查询单个 | ✅ 幂等 |
| `POST` | `/api/users` | 新增用户 | ❌ 非幂等 |
| `PUT` | `/api/users/{id}` | 更新用户 | ✅ 幂等 |
| `DELETE` | `/api/users/{id}` | 逻辑删除 | ✅ 幂等 |

> **幂等性**：多次执行同一请求，结果一致。GET/PUT/DELETE 是幂等的，POST 不是（多次 POST 会创建多条记录）。

**`@Valid` 的工作流程：**
```
客户端 POST JSON
    │
    ▼
@Valid @RequestBody User user
    │
    ├─ username = "张三"  → @NotBlank ✅ 通过
    ├─ phone = "123"      → @Pattern  ❌ 不匹配 → 抛出 BindException
    │
    ▼
GlobalExceptionHandler 捕获 BindException
    │
    ▼
返回: { "code": 500, "message": "phone: 手机号格式不正确" }
```

### 3.7 Config 层 — MyBatis-Plus 插件配置

```java
@Configuration
public class MyBatisPlusConfig {

    // ========== 分页插件 ==========
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 添加 MySQL 分页拦截器
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }

    // ========== 自动填充处理器 ==========
    @Bean
    public MetaObjectHandler metaObjectHandler() {
        return new MetaObjectHandler() {
            @Override
            public void insertFill(MetaObject metaObject) {
                LocalDateTime now = LocalDateTime.now();
                // 插入时填充 createTime 和 updateTime
                this.strictInsertFill(metaObject, "createTime", LocalDateTime.class, now);
                this.strictInsertFill(metaObject, "updateTime", LocalDateTime.class, now);
            }

            @Override
            public void updateFill(MetaObject metaObject) {
                // 更新时只填充 updateTime
                this.strictUpdateFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
            }
        };
    }
}
```

**配合关系：**
```
@TableField(fill = FieldFill.INSERT)          ← 标记字段
        │
        ▼
MetaObjectHandler.insertFill()                ← 填充逻辑
        │
        ▼
执行 INSERT 时自动设置 createTime = LocalDateTime.now()
```

> **为什么需要分页插件？** MyBatis-Plus 的 `Page` 对象本身只是数据容器。**分页拦截器**会在 SQL 执行前自动读取 `Page` 参数，拼接 `LIMIT` 和 `OFFSET`，同时执行 `COUNT` 查询获取总数。不配置拦截器，分页不会生效。

### 3.8 统一响应与全局异常

**统一响应体 `Result<T>`：**

```java
@Data
public class Result<T> {
    private Integer code;     // 200=成功，其他=失败
    private String message;   // 提示信息
    private T data;           // 泛型数据，可以是任意类型

    public static <T> Result<T> ok(T data) {
        Result<T> r = new Result<>();
        r.code = 200;
        r.message = "success";
        r.data = data;
        return r;
    }

    public static <T> Result<T> fail(String message) {
        Result<T> r = new Result<>();
        r.code = 500;
        r.message = message;
        return r;
    }
}
```

**为什么需要统一响应体？** 前端只需要处理一种 JSON 结构，不管是成功还是失败：

```json
// 成功
{ "code": 200, "message": "success", "data": { "records": [...], "total": 15 } }

// 失败
{ "code": 500, "message": "phone: 手机号格式不正确", "data": null }
```

**全局异常处理器：**

```java
@RestControllerAdvice                           // 拦截所有 @RestController 的异常
public class GlobalExceptionHandler {

    @ExceptionHandler(BindException.class)       // 专门处理参数校验失败
    public Result<Void> handleBindException(BindException e) {
        // 把所有字段错误拼成一条消息
        String msg = e.getBindingResult().getFieldErrors()
                .stream()
                .map(f -> f.getField() + ": " + f.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return Result.fail(msg);
    }

    @ExceptionHandler(Exception.class)           // 兜底处理所有其他异常
    public Result<Void> handleException(Exception e) {
        return Result.fail(e.getMessage());
    }
}
```

**异常处理流程：**
```
Controller 抛出异常
        │
        ▼
@RestControllerAdvice 扫描匹配的 @ExceptionHandler
        │
        ├─ BindException  →  handleBindException() → 返回友好的校验错误
        ├─ 其他 Exception →  handleException()     → 返回通用错误
        │
        ▼
    前端收到统一的 Result JSON
```

## 4. 前端详解

### 4.1 架构设计 — API / Mock 双模式

前端 `app.js` 使用 **IIFE（立即执行函数表达式）** 包裹全部逻辑，避免全局变量污染：

```javascript
(function () {
    'use strict';
    // 所有变量和函数都在这个闭包内，外部不可访问
})();
```

**双模式自动切换机制：**

```javascript
var API_BASE = 'http://localhost:8080/api/users';
var API_TIMEOUT = 2000;    // 超时 2 秒

function init() {
    var controller = new AbortController();
    var timer = setTimeout(function () { controller.abort(); }, API_TIMEOUT);

    // 发送探测请求
    fetch(API_BASE + '?page=1&size=1', { signal: controller.signal })
        .then(function (r) { return r.json(); })
        .then(function (json) {
            clearTimeout(timer);
            if (json.code === 200) {
                useApi = true;           // ← 后端可达，走 API 模式
                setModeUI('live');
            }
            renderTable();
        })
        .catch(function () {
            clearTimeout(timer);
            useApi = false;              // ← 后端不可达，走 Mock 模式
            setModeUI('mock');
            renderTable();
        });
}
```

**设计思路：** 前端启动时发一个最小请求（只取 1 条数据），如果 2 秒内有正确响应就认为后端在线。这使得同一个前端文件既可以**独立运行**（Mock 模式，用内置种子数据），也可以**对接后端**（API 模式）。

### 4.2 数据层 — fetch 与本地存储切换

**核心抽象：** 所有数据操作通过三个入口函数，内部判断 `useApi` 标志决定走哪条路径。

```javascript
function fetchPage(page, size, keyword) {
    if (useApi) {
        // ===== API 模式 =====
        var params = '?page=' + page + '&size=' + size;
        if (keyword) params += '&keyword=' + encodeURIComponent(keyword);
        return fetch(API_BASE + params)
            .then(function (r) { return r.json(); })
            .then(function (json) {
                totalRecords = json.data.total;    // 服务器返回的总数
                return json.data.records;          // 当前页数据
            });
    } else {
        // ===== Mock 模式 =====
        var filtered = mockUsers.filter(/* 按 keyword 过滤 */);
        totalRecords = filtered.length;
        var start = (page - 1) * size;
        return Promise.resolve(filtered.slice(start, start + size));
    }
}
```

**`Promise.resolve()` 的作用：** 在 Mock 模式下，数据是同步计算的，但为了保持和 API 模式一致的异步接口（都返回 Promise），用 `Promise.resolve()` 把同步结果包装成 Promise。这样上层调用代码不需要区分模式：

```javascript
// 上层代码两种模式都一样
```

### 4.3 渲染层 — 表格与分页

**表格渲染：** 使用模板字符串拼接 HTML，通过 `innerHTML` 一次性插入 DOM，避免多次 DOM 操作。

```javascript
tableBody.innerHTML = records.map(function (u) {
    return '<tr>' +
        '<td>' + u.id + '</td>' +
        '<td>' + escHtml(u.username) + '</td>' +
        // ...
        '<td><button data-edit="' + u.id + '">编辑</button></td>' +
    '</tr>';
}).join('');
```

**`escHtml()` — 防 XSS 攻击：**

```javascript
function escHtml(str) {
    var div = document.createElement('div');
    div.textContent = str;   // textContent 自动转义 HTML 标签
    return div.innerHTML;    // 返回转义后的安全字符串
}
// escHtml('<script>alert(1)</script>') → '&lt;script&gt;alert(1)&lt;/script&gt;'
```

> **为什么需要转义？** 如果用户名是 `<img src=x onerror=alert(1)>`，直接拼入 HTML 会导致 XSS 攻击。`escHtml()` 将特殊字符转为 HTML 实体，确保数据以纯文本显示。

**分页控件生成逻辑：**

```javascript
function renderPagination(totalPages) {
    var h = '';
    // 上一页按钮
    h += '<button ' + (currentPage <= 1 ? 'disabled' : '') +
         ' data-page="' + (currentPage - 1) + '">上一页</button>';

    // 生成页码按钮（最多显示 6 个）
    var maxVisible = 6;
    var sp = Math.max(1, currentPage - 3);   // 起始页码
    var ep = Math.min(totalPages, sp + 5);    // 结束页码

    if (sp > 1) { h += '<button data-page="1">1</button>'; /* ... */ }

    for (var p = sp; p <= ep; p++) {
        h += '<button class="' + (p === currentPage ? 'active' : '') +
             '" data-page="' + p + '">' + p + '</button>';
    }

    if (ep < totalPages) { /* ... */ h += '<button data-page="' + totalPages + '">' + totalPages + '</button>'; }

    h += '<button ' + (currentPage >= totalPages ? 'disabled' : '') +
         ' data-page="' + (currentPage + 1) + '">下一页</button>';
    paginationCtls.innerHTML = h;
}
```

**渲染效果示例（当前在第 5 页，共 10 页）：**
```
[上一页] [1] [...] [3] [4] [5] [6] [7] [...] [10] [下一页]
                  ↑ active
```

### 4.4 交互层 — 模态弹窗与表单校验

**事件委托模式：** 不在每个按钮上单独绑定事件，而是在父容器上监听，通过 `data-*` 属性判断操作目标。这样即使表格重新渲染，事件依然有效。

```javascript
// 表格中的编辑/删除按钮
tableBody.addEventListener('click', function (e) {
    var editBtn = e.target.closest('[data-edit]');
    var delBtn  = e.target.closest('[data-delete]');
    if (editBtn) openEditModal(parseInt(editBtn.getAttribute('data-edit')));
    if (delBtn)  openDeleteConfirm(parseInt(delBtn.getAttribute('data-delete')));
});

// 分页按钮
paginationCtls.addEventListener('click', function (e) {
    var btn = e.target.closest('button[data-page]');
    if (btn && !btn.disabled) {
        currentPage = parseInt(btn.getAttribute('data-page'));
        renderTable();
    }
});
```

**客户端表单校验：**

```javascript
function validateForm(data) {
    var valid = true;
    // 清空上次错误
    clearFormErrors();

    // ① 用户名为空
    if (!data.username.trim()) {
        showFieldError('errorUsername', '用户名不能为空', 'inputUsername');
        valid = false;
    }

    // ② 手机号格式（与服务端正则一致）
    var phoneRe = /^1[3-9]\d{9}$/;
    if (!data.phone.trim()) {
        showFieldError('errorPhone', '手机号不能为空', 'inputPhone');
        valid = false;
    } else if (!phoneRe.test(data.phone.trim())) {
        showFieldError('errorPhone', '手机号格式不正确（11位，1开头）', 'inputPhone');
        valid = false;
    }

    // ③ 邮箱格式（选填）
    if (data.email.trim()) {
        var emailRe = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
        if (!emailRe.test(data.email.trim())) {
            showFieldError('errorEmail', '邮箱格式不正确', 'inputEmail');
            valid = false;
        }
    }
    return valid;
}
```

> **双重校验策略：** 前端校验提升用户体验（即时反馈），后端 `@Valid` 校验保证数据安全（不可绕过）。两者正则表达式保持一致。
