# 回映 Rewind 未来拓展规划

> 本文档整理了项目的拓展方向，按性价比分为三个梯队。每个方向附带可直接使用的 AI 提示词，复制后发给 AI 即可协助实现。

## 第一梯队：必须做（投入小，收益大）

### 1. 代码工程化重构

**目标**：将单文件 `app.py` 拆分为模块化结构，提升可维护性。

**技术要点**：
- 拆分为 `routes/`（路由）、`models/`（数据库操作）、`services/`（业务逻辑）、`config.py`（配置）
- 配置项从硬编码改为配置文件或环境变量
- `print` 替换为 `logging` 日志模块
- 入口文件 `run.py` 单独启动

**提示词**：

```
请帮我重构这个 Flask 项目，当前所有代码都在 app.py 一个文件里。

项目结构：
- app.py：包含 Flask 应用、路由、数据库操作、设备识别中间件
- templates/index.html：播放页
- templates/admin.html：仪表盘页
- 数据库：SQLite，三张表 devices / progress / watch_sessions

请重构为以下结构：
- run.py：启动入口
- config.py：配置类（视频目录、端口、数据库路径等，支持从环境变量读取）
- app/__init__.py：创建 Flask app，注册路由
- app/routes.py：所有页面路由和 API 路由
- app/database.py：数据库连接、初始化、查询函数
- app/middleware.py：设备识别中间件
- app/utils.py：工具函数（scan_videos、safe_resolve 等）

要求：
1. 保持所有现有功能不变（视频播放、断点续播、观看记录、仪表盘）
2. 使用 logging 模块替代 print，日志输出到控制台和文件
3. 数据库操作用函数封装，路由层不直接写 SQL
4. 给出完整的代码文件和重构说明
```

### 2. 单元测试

**目标**：用 pytest 为核心逻辑编写单元测试。

**技术要点**：
- 测试 `safe_resolve()` 的路径遍历防护（正常路径、`../`、绝对路径、边界情况）
- 测试数据库的增删改查
- 测试 API 接口（用 Flask 的 `test_client`）
- 测试设备识别中间件

**提示词**：

```
请为我的 Flask 视频流媒体项目编写单元测试，使用 pytest。

项目核心文件 app.py 包含：
- safe_resolve(rel_path)：路径安全校验函数，防止目录遍历
- scan_videos(root_dir)：递归扫描视频文件
- 数据库表：devices、progress、watch_sessions
- API 接口：/api/progress (GET/POST)、/api/play (POST)、/api/end (POST)、/api/stats (GET)、/api/devices (GET)、/api/devices/<id>/tag (POST)
- 设备识别：通过 Cookie device_id 识别设备，before_request 中间件

请编写 tests/ 目录下的测试文件：
- test_utils.py：测试 safe_resolve 的各种边界情况（正常相对路径、含../的路径、绝对路径、空路径、根目录本身）
- test_api.py：用 Flask test_client 测试所有 API 接口的正常和异常情况
- test_database.py：测试数据库的 CRUD 操作

要求：
1. 使用 pytest + pytest-flask
2. 测试数据库使用临时文件，测试结束自动清理
3. 每个测试函数有明确的断言
4. 给出测试文件代码和运行命令
```

### 3. Docker 部署

**目标**：容器化部署，支持一键启动。

**技术要点**：
- `Dockerfile`：基于 Python 镜像，安装依赖，复制代码
- `docker-compose.yml`：端口映射、卷挂载（视频目录和数据库）
- 使用 Gunicorn 作为生产 WSGI 服务器
- 视频目录通过 volume 挂载到容器内

**提示词**：

```
请为我的 Flask 视频流媒体项目添加 Docker 部署支持。

项目信息：
- 主程序：app.py，监听 0.0.0.0:5000
- 模板目录：templates/
- 视频目录：默认 D:\电视剧，可通过 video_dir.txt 配置
- 数据库：rewind.db，自动创建在程序同目录
- 依赖：flask（Python 3.14）

请生成：
1. Dockerfile：基于 python:3.14-slim，安装 flask 和 gunicorn，暴露 5000 端口
2. docker-compose.yml：映射 5000 端口，挂载视频目录和数据卷
3. .dockerignore：排除 __pycache__、*.pyc、rewind.db、dist/、build/ 等
4. requirements.txt：列出依赖

要求：
- 容器内视频目录路径设为 /videos，通过环境变量 VIDEO_ROOT 配置
- 数据库持久化到命名卷 rewind_data
- 使用 gunicorn -w 4 -b 0.0.0.0:5000 app:app 启动
- 给出 docker-compose up -d 启动说明和注意事项（视频目录挂载路径）
```

## 第二梯队：技术深度（选做 1-2 个）

### 4. FFmpeg 视频实时转码

**目标**：对浏览器不支持的格式（如 MKV）实时转码为 MP4 分片播放。

**技术要点**：
- 集成 `ffmpeg` 命令行工具
- 检测视频格式，不兼容时启动 ffmpeg 转码进程
- 转码为 HLS（m3u8 + ts 分片）或流式 MP4
- 转码进程管理（启动、停止、超时回收）
- 性能考虑：转码缓存、并发限制

**提示词**：

```
请为我的 Flask 视频流媒体服务器添加 FFmpeg 实时转码功能。

当前项目：
- app.py 中 /video/<path:filename> 路由用 send_file 直接返回视频文件
- 支持 mp4/mkv/avi，但手机浏览器对 mkv/avi 兼容性差
- 已正确处理 HTTP Range 请求

需求：
1. 当请求的视频是 mkv/avi 等浏览器不兼容格式时，自动用 ffmpeg 实时转码为 mp4
2. 转码后的视频仍需支持 HTTP Range（拖动进度条）
3. 转码进程需要管理：用户关闭页面后自动终止，防止资源泄漏
4. 兼容格式（mp4）仍走原来的 send_file 直出，不转码
5. 可以选择转码为 HLS 分片（m3u8）或流式 mp4，选你认为更合适的方案并说明理由

技术要求：
- 使用 Python subprocess 调用系统 ffmpeg
- 转码输出通过 Flask 流式返回（Response + generator）
- 设置合理的 ffmpeg 参数（-c:v libx264 -preset ultrafast -c:a aac）
- 前端 video 标签可能需要切换为 hls.js 来播放 m3u8
- 给出完整的代码修改和前端适配
```

### 5. 用户系统与权限

**目标**：添加注册登录，每个用户独立观看记录，管理员才能看仪表盘。

**技术要点**：
- 用户表：id、用户名、密码哈希、角色（admin/user）
- 密码用 `werkzeug.security` 的 `generate_password_hash` / `check_password_hash`
- 登录用 Session 或 JWT
- 观看记录从"按设备"改为"按用户"
- 仪表盘 `/admin` 仅管理员可访问
- 注册页面、登录页面

**提示词**：

```
请为我的 Flask 视频流媒体项目添加用户注册登录系统和权限控制。

当前项目：
- 设备识别通过 Cookie device_id（before_request 中间件）
- 观看记录按设备存储（watch_sessions.device_id）
- 仪表盘 /admin 无密码，任何人可访问
- 数据库 SQLite，已有 devices / progress / watch_sessions 三张表

需求：
1. 新增 users 表：id、username、password_hash、role（admin/user）、created_at
2. 注册页面 /register：用户名+密码，密码用 werkzeug.security 哈希存储
3. 登录页面 /login：验证后写入 Flask session
4. 登出 /logout
5. 观看记录改为按用户存储：watch_sessions 增加 user_id 字段，登录用户的记录关联到用户
6. 未登录用户仍可观看，但记录关联到 device_id（兼容现有逻辑）
7. /admin 仪表盘仅 role=admin 的用户可访问，普通用户访问返回 403
8. 页面右上角显示当前用户名和登出按钮

要求：
- 给出数据库迁移方案（ALTER TABLE 添加字段）
- 登录注册页面要适配现有深色主题和响应式设计
- 第一个注册的用户自动成为管理员
- 完整代码修改说明
```

### 6. 视频缩略图与详情页

**目标**：用 FFmpeg 截取视频首帧作为封面，增加视频详情页。

**技术要点**：
- 视频首次被扫描时，用 ffmpeg 截取第 1 秒的帧作为缩略图
- 缩略图缓存到 `thumbnails/` 目录
- 视频列表显示封面图而非纯文字
- 点击视频进入详情页 `/watch/<video>`，显示封面、文件名、时长、观看进度、相关推荐
- 详情页内嵌入播放器

**提示词**：

```
请为我的 Flask 视频流媒体项目添加视频缩略图和详情页功能。

当前项目：
- 首页 / 列出所有视频，纯文字列表，点击直接在页面内播放
- 视频扫描函数 scan_videos() 返回相对路径列表
- 数据库有 progress 表记录播放进度

需求：
1. 用 ffmpeg 为每个视频截取第 5 秒的画面作为缩略图，保存到 thumbnails/ 目录
2. 缩略图生成是异步的（首次访问时触发，不阻塞页面加载），生成前显示占位图
3. 新增路由 /watch/<path:filename> 视频详情页：
   - 显示视频封面大图
   - 显示文件名、所在目录、文件大小、视频时长
   - 嵌入 HTML5 video 播放器
   - 显示观看进度条（已看 45%）
   - 显示"续播"和"从头播放"两个按钮
4. 首页视频列表改为卡片式布局，显示缩略图 + 文件名 + 进度徽章
5. 新增 /thumbnail/<path:filename> 路由返回缩略图图片

技术要求：
- ffmpeg 截图命令：ffmpeg -ss 5 -i input -vframes 1 -q:v 2 output.jpg
- 缩略图文件名用视频路径的 md5 哈希，避免特殊字符问题
- 详情页保持现有深色主题和响应式设计
- 给出完整的代码修改
```

## 使用说明

2. 粘贴给 AI 助手（如豆包），并附上当前的 `app.py` 代码

4. 建议一次只做一个方向，完成后再做下一个，避免代码冲突
5. 每次修改后先运行测试确认功能正常，再继续下一项
